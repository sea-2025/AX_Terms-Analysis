# 개인정보 문서 분석 최소 실행 프로그램

UTF-8 텍스트 문서 1개를 읽어 OpenAI Chat Completions API로 분석합니다. 제공자는 **OpenAI**, 실행 예시 모델은 **gpt-4.1-mini**입니다. 모델과 키는 실행 환경에서 설정하며 Python 코드에는 저장하지 않습니다. Python 3.10 이상이 필요하며 추가 패키지 설치는 필요 없습니다. 실제 호출에는 API 사용 권한, 네트워크 연결과 비용이 필요합니다.

## 예·적금 상품 분석 MVP

서버를 실행한 뒤 **http://127.0.0.1:8000/products** 에 접속합니다. 같은 상품의 공개 약관·상품설명서·금리표를 최대 6개 입력하면 금리와 우대조건, 수수료, 중도해지 조건을 분석합니다. 문서별 상품명이 분석할 상품명과 같아야 합니다. 입력자가 적은 상품명은 일치 여부를 자동으로 보증하지 않으므로 실제 문서도 확인해야 합니다. 서로 다른 상품은 따로 분석하세요.

분석 시 `rules/`의 네 규칙 파일을 고정 지시문에 넣고, 문서 전체는 별도의 사용자 메시지로 한 번의 Chat Completions 요청에 전송합니다. Structured Outputs 형식을 사용하며 자동 재시도나 문서 조각별 요청은 없습니다. 입력 문서 본문의 합계가 **10,000자**를 넘으면 호출하지 않고 안내합니다.

요청 본문 전체의 UTF-8 바이트 수를 보수적인 토큰 상한 추정치로 사용하고 메시지 여유 2,048토큰과 최대 출력 8,192토큰을 더해 모델의 문맥 한도를 검사합니다. 이 방법은 정확한 토크나이저 계산이 아닙니다. 확인된 GPT-4.1 mini·GPT-4.1·GPT-4o mini·GPT-4o와 코드에 명시된 스냅샷만 지원하며, 한도를 확인하지 않은 모델은 호출 전 거부합니다. 규칙 파일이 없거나 예상된 규칙 ID가 중복·누락되면 분석을 중단합니다.

문단 ID와 인용문을 원문에 대조합니다. 근거가 잘못된 사실과 해당 카드의 핵심 설명은 숨기고 부분 완료로 표시합니다. 인용이 일치해도 설명의 의미, 숫자와 적용 조건이 정확하다는 보장은 없습니다. 상품 약관에 적힌 시점과 조건을 직접 확인하세요. 수수료 미확인은 무료를 뜻하지 않습니다. 분석 대상이 개인정보 동의서 등일 경우 예·적금 문서가 필요하다고 안내합니다.

요청과 결과의 본문은 서버 운영 로그에 기록하거나 저장하지 않습니다. 기존 개인정보 분석은 계속 **http://127.0.0.1:8000/** 에서 사용할 수 있습니다. `tests/fixtures/fictional-deposit.txt`는 프로그램 동작을 시험하기 위한 가상 문서이며 실제 은행 상품이 아닙니다.

## 로컬 웹 화면

이 폴더의 `.env`에 `OPENAI_API_KEY`와 `OPENAI_MODEL`을 설정한 뒤 PowerShell에서 실행합니다. 위 환경 변수가 이미 설정되어 있다면 환경 변수가 우선합니다.

```powershell
python .\web.py
```

브라우저에서 **http://127.0.0.1:8000/** 에 접속합니다. 공개 문서 텍스트를 붙여 넣고 입력 범위를 선택한 뒤 분석합니다. 서버를 종료하려면 실행 중인 PowerShell에서 Ctrl+C를 누릅니다. 브라우저 분석은 호출당 API 비용이 발생하며 입력 내용은 OpenAI에 전송됩니다. 실제 개인정보는 입력하지 마세요.

입력 범위는 사용자 선택을 표시할 뿐 원본 전체 여부를 검증하지 않습니다. 서버는 로컬 주소에서만 실행되고 문서, 결과, 키를 파일이나 운영 로그에 저장하지 않습니다. 결과는 현재 브라우저 화면에만 표시됩니다.

## 시험 문서 준비

`sample.txt`는 다음 공식 문서의 텍스트입니다.

https://image.kebhana.com/cont/customer/customer07/customer0701/customer070106/__icsFiles/afieldfile/2025/08/20/3-08-1294.pdf

다운로드한 PDF에서 `pdftotext -layout -enc UTF-8`으로 추출하고 PDF 화면을 대조했습니다. 추출 과정에서 표의 제목과 내용이 서로 엇갈려, 공백과 줄 배치를 조정하고 제목을 대응하는 내용 앞에 배치했습니다. 추출된 공백을 제외한 모든 문자가 보존되는지 검사했습니다. 문단이나 표의 관련 항목 사이에는 빈 줄을 넣었습니다. PDF 처리 기능은 제공하지 않습니다.

## 설정 및 실행 (PowerShell)

이 폴더에서 아래 명령을 실행합니다. 키는 화면에 표시되지 않는 입력창에 넣으며, 현재 PowerShell 프로세스에서만 설정됩니다. 키를 채팅, 파일 또는 명령 기록에 직접 적지 마세요.

```powershell
$secret = Read-Host 'OpenAI API 키' -AsSecureString
$secretPtr = [Runtime.InteropServices.Marshal]::SecureStringToBSTR($secret)
try { $env:OPENAI_API_KEY = [Runtime.InteropServices.Marshal]::PtrToStringBSTR($secretPtr) }
finally { [Runtime.InteropServices.Marshal]::ZeroFreeBSTR($secretPtr); Remove-Variable secret, secretPtr }
$env:OPENAI_MODEL = 'gpt-4.1-mini'
python .\analyze.py .\sample.txt
```

정상 분석 시 6개 항목의 상태, 설명과 문단 번호별 원문 근거가 화면과 `result.json`에 출력됩니다. 다른 출력 파일을 지정하려면 `python .\analyze.py .\sample.txt --output .\result.json`을 사용하세요. 이 결과 파일은 의도된 분석 산출물이며 원문 인용을 포함합니다. 로그 파일은 만들지 않습니다. 입력 내용은 OpenAI API로 전송됩니다.

`--audit audit.json`을 지정하면 API 응답의 HTTP 상태, 요청 ID, 응답 ID, 모델과 수신 시각을 별도 파일에 저장합니다. 감사 파일에는 API 키, 입력 본문, 모델 응답과 결과를 저장하지 않습니다. 요청이 응답을 받기 전에 실패하거나 응답이 완료되지 않으면 감사 파일을 새로 쓰지 않습니다. 기존 파일이 남아 있을 수 있으므로 새 파일명을 사용하세요. 분석 결과의 표준 출력에는 원문 인용이 포함되므로 본문을 출력하거나 기록하지 않으려면 PowerShell에서 `> $null`을 추가하세요. 감사 파일은 응답을 받았다는 실행 기록이며 별도 서버 기록을 검증한 증명서는 아닙니다.

빈 줄로 구분된 텍스트 블록에 순서대로 `P0001`부터 번호를 붙입니다. 모델은 근거 문단 번호를 지정하고 프로그램이 해당 문단 전체를 원문에서 복사합니다. 존재하지 않는 문단 번호 등 근거 확인에 실패하면 해당 항목을 `근거 확인 실패`로 표시하고 종료 코드 1을 반환합니다. 이전 형식의 인용문이 응답에 포함된 경우에는 해당 문단과 정확히 일치하는지도 검사합니다. 모델이 해당 항목을 찾지 못한 경우 `입력에서 확인되지 않음`으로 표시합니다. 이 표시는 입력 범위에 한정되며 부재를 보증하지 않습니다. 원문 복사는 모델이 올바른 문단을 선택했는지, 설명이 정확한지 또는 조건·예외가 빠지지 않았는지 보장하지 않으므로 원문과 대조해야 합니다.

API 오류, 응답 형식 오류, 입력 파일 오류는 별도 오류로 처리하고 결과를 저장하지 않습니다. 이전 `result.json`이 있다면 그대로 남으므로 파일의 수정 시각에 유의하세요. 종료 코드는 성공 0, 오류 또는 근거 확인 실패 1, 설정·입력 범위 오류 2입니다.

검증 테스트:

```powershell
python -m unittest discover -s tests -v
```

프로그램은 이 폴더의 `.env`에서 `OPENAI_API_KEY=값`과 `OPENAI_MODEL=값`을 읽을 수도 있습니다. 같은 이름의 환경 변수가 설정되어 있으면 환경 변수를 우선합니다. `.env`, `.env.*`, `*.key`, `*.pem`은 Git 추적에서 제외하며, 키 파일을 공유하지 마세요.

## 파일 구성

- `analyze.py`: CLI와 웹 화면이 공유하는 분석·근거 검증
- `product_analysis.py`: 상품 분석 지시문·입력 조립·단일 API 호출·서버 검증
- `rules/`: 상품 분석용 공통·금리·수수료·중도해지 규칙
- `web.py`, `web_static/`: 로컬 웹 서버와 화면
- `sample.txt`: 공개 시험 문서
- `tests/`: CLI·서버·브라우저 검증
- `docs/`: 기획 문서와 샘플 원본 PDF
- `artifacts/`: 이전 분석 결과와 호출 기록. Git에서 제외됩니다.
- `legacy/`: 이전 웹 실험 코드와 테스트 보관본
