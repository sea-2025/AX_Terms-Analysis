# 우리 첫거래우대 정기예금 원문 대조 및 분석 준비 점검

검토일: 2026-11-25. 자료는 우리은행 명칭과 심의필 `2026-8682(2026.09.10~2027.09.09)`이 표시된 6쪽 상품설명서다. 사용자가 지정한 폴더에는 초안만 있었으므로, 이전 검증에 보관된 PDF와 텍스트를 각각 `original.pdf`, `input.txt`로 복사했다. PDF는 다운로드 폴더의 해당 상품설명서와 SHA-256이 같았다: `a2e7ca291f33c4fbdfa33a5a90d93b9bef5dc4d5bc2d56ac680b9da71f7889c4`. 배포처의 진위는 별도로 확인하지 않았다.

이 문서는 PDF의 표시 내용과 추출 텍스트, 예상 결과 초안을 직접 대조한 기록이다. 기존 AI 분석 결과는 정답 근거로 사용하지 않았다. 초안은 그대로 두고 수정 제안만 적는다.

## 1. 입력 텍스트와 PDF

- `input.txt`는 6,849자이며 PDF 전체에서 추출된 기존 텍스트다. 페이지 구분자 6개가 있고 문자 대체 기호는 발견되지 않았다. 이는 모든 글자와 표 구조의 완전한 일치를 보장하지 않는다.
- 1쪽 기본금리 표는 세 개 기간과 연 2.60%, 2.80%, 2.20%의 열 순서가 텍스트에 남아 있다. 그러나 같은 쪽의 상품유형·거래방법·가입금액·계약기간 등의 왼쪽 행 제목이 내용보다 먼저 연속해서 나와, 어떤 제목이 어느 내용에 속하는지 텍스트만으로 오인할 수 있다.
- 2쪽 우대조건 ①~③, 각 이율, 최대 연 1.0%p, 마케팅 동의 유지 조건 및 주1의 기간 정의는 추출되어 있다. 다만 `중도해지이율` 표제가 우대조건 설명 중간에 끼어 있어 항목 경계가 흐트러졌다.
- 2쪽 중도해지 표의 기간별 산식 수치는 추출됐지만, 네 산식 행에 걸친 `최저이율 연 0.15%` 병합 셀이 6~9개월, 9~11개월 행 옆의 텍스트로 나타난다. 추출 텍스트만으로 어느 행 전체에 적용되는지 명확히 보존되지 않는다. PDF 화면의 병합 셀은 3개월 이상인 네 산식 행에 걸쳐 있고 3개월 미만 연 0.1% 행에는 걸치지 않는다.
- 2쪽 산출근거 그래프는 그림으로 표시되며 그래프 내용은 텍스트에 완전하게 재현되지 않는다. 표에 해당 산식은 있으나 그림 자체를 입력에 포함한 것은 아니다. 6쪽의 용어 표에서도 `출연` 행 제목이 위 행 근처로 이동한다.
- 따라서 **글자가 일부 보존된 것과 표의 의미가 정확히 전달되는 것은 다르다**. 현재 추출본을 사용한 모델 결과는 원문 PDF를 대조해 검증해야 하며, 정확성 평가용 입력으로는 표 관계 복원이 필요하다. 임의로 원문을 편집하거나 표를 복원하지 않았다.

## 2. 예상 결과표 검토와 수정 제안

PDF 1쪽의 기본금리 기간별 매칭과 2쪽 우대 상한·각 조건의 금리, 2쪽 중도해지의 기간별 산식은 초안의 주요 수치와 일치한다. 3쪽 분할해지 횟수, 4쪽 조건부 위법계약해지 관련 수수료 내용도 확인된다. 다음은 초안의 모호성 또는 빠진 제한을 보완하기 위한 제안이다.

|---|---|---|
| INT-05 | 2쪽 주1은 단순한 직전 365일이 아니라 기간의 시작과 끝을 별도로 정의한다. | `신규 직전 1년은 이 예금 신규월로부터 1년 전부터 예금 신규 전전월 말까지`라는 정의를 예상 결과 본문에 직접 추가한다. |
| TERM-07 | 2쪽 병합 셀은 3개월 이상인 네 계산식 행에 걸쳐 있다. | `3개월 이상~6개월 미만, 6개월 이상~9개월 미만, 9개월 이상~11개월 미만, 11개월 이상의 네 행에 최저 연 0.15%가 표시되며 3개월 미만 연 0.1% 행은 제외`라고 명확히 적는다. |

## 3. API 호출 전 준비 상태

- 로컬 `.env` 또는 환경변수에서 API 키와 모델 설정이 존재함을 확인했다. 키 값은 출력하거나 기록하지 않았다. 현재 설정 모델은 `gpt-4.1-mini`다. 설정 존재는 키 유효성, 네트워크, 결제 또는 실제 호출 성공을 보장하지 않는다.
- 6,849자는 10,000자 제한 이내다. 기존 `prepare_documents`와 `build_payload`를 네트워크 없이 실행해 입력 1건과 72개 문단을 구성하고 요청 생성에 성공했다.
- 요청의 `system`에 4개 규칙 파일의 중복 없는 규칙 ID 76개가 포함되고, 별도 `user` 메시지에 입력 텍스트가 보존됨을 검사했다. 초안 전체와 초안 제목 표식은 두 메시지에 포함되지 않았다. 이는 이번에 구성한 요청에 대한 확인이며, 실제 화면에서 사용자가 정답표를 붙여 넣으면 이를 자동으로 구분한다는 뜻은 아니다.
- **기술적 요청 생성은 가능하지만, 현재 입력의 표 제목과 병합 셀이 흐트러져 정확성 검증용으로는 주의가 필요하다.** PDF와 텍스트 비교를 거쳐 표 관계를 보존한 별도 입력을 마련하거나, 현 추출본 그대로의 한계를 명시하고 결과를 평가해야 한다.
- 이번 단계의 실제 API 호출은 0회다. 기존 분석 코드와 규칙은 변경하지 않았다. 요청 생성만으로 실제 연결·응답·분석 품질을 검증하지 않았다.
