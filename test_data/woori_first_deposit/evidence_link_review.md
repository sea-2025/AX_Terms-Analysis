# 문단 ID 기반 근거 연결 검증

> 이 보고서는 문단 ID 기반 연결을 적용한 당시의 중간 검증 결과입니다. 이후 실제 API 검증과 화면 표시 수정이 진행됐습니다. 실제 API 응답은 저장소에 포함하지 않습니다.

2026-11-27 최종 점검의 저장 응답 `artifacts/final_validation_20261127/result.json`을 수정 전후 코드로 재처리했다. 실제 API는 추가 호출하지 않았다. 원본 응답과 수정 전 결과는 덮어쓰지 않았다.

## 변경 방식

- 새 모델 응답 형식은 인용문 대신 문서 ID와 문단 ID를 반환한다. 여러 문단이 필요하면 ID를 각각 반환한다. 기존 저장 응답의 `quote` 필드는 호환을 위해 받아들이되, 인용 내용으로 사용하지 않는다.
- 서버가 해당 문단 ID를 입력 문서에서 찾아 실제 원문 전체와 위치를 복사한다. 존재하지 않는 문서·문단 ID는 해당 사실의 `validation_failed`로 처리한다.
- 문단을 찾은 것만으로 모델 설명과 조건이 맞다고 판정하지 않는다. 일반적인 모델 설명은 `needs_review`로 남기며, 인식 가능한 표의 행·열에서 서버가 별도로 추출한 값만 표시한다. 이 경우에도 `claim_status`와 조건 완전성은 `needs_review`다.
- 모델 출력에 우대조건의 적용 대상, 기간 정의, 예외·제외에 대한 `condition_fields`를 추가했다. 값이 비어 있거나 미확인이면 `condition_fields_missing`으로, 값이 있어도 지정 문단에 문자 그대로 없으면 `condition_fields_unverified`로 추가 확인한다. 문자 일치만으로 의미까지 입증되는 것은 아니므로 일치한 경우에도 해석은 추가 확인 상태다. 이전 저장 응답에는 이 구조화 필드가 없으므로 확인 필요로 처리하며, 원문에 해당 내용이 없다고 단정하지 않는다.

## 검증

- 저장된 최종 응답의 변경 전 결과를 재현하고, 수정 후 4건의 상태·문단 ID·원문 위치를 비교했다. 두 개 이상의 문단은 각각 별도의 근거로 유지되는지도 확인했다.
- Python 테스트 62개가 통과했다. 모의 응답으로 없는 ID 거부, 기존 AI 인용문 무시, 문단은 존재하지만 설명과 관계없는 경우의 추가 확인, 빈 우대 필드 및 원문 불일치 경고, 문자 일치만으로 의미를 확정하지 않는 처리, 독립적으로 확인한 표 값 유지 및 CRLF 원문 위치를 검사했다.
