# 우리은행 저장 응답 오류 원인과 오프라인 수정 검증

분석 대상은 저장된 `result_woori.json`의 실제 AI 응답, 이전 후처리 결과 `validated_woori.json`, `review_woori.md`, `input_verified.txt`, `woori_expected_results_draft.md`, 기존 분석 코드 및 규칙이다. API를 재호출하지 않았다. 원본 결과는 수정하지 않았다.

## 수정 범위와 안전장치의 한계

- `product_analysis.py`: 기존 원문 문자열 일치 검사는 유지한다. 독립적인 의미 검증 없이 인용 일치만으로 AI 문장이나 조건을 `found`로 확정하던 문제를 피하기 위해, 정확히 일치한 인용만 보존하고 해당 사실은 `needs_review`로 표시한다. 모델이 제출한 요약·조건·미확인 문구와 상품 설명 메모는 확정 결과에 노출하지 않는다. 문서 날짜도 문자열 일치만으로 유형을 확정하지 않는다. 차단 대상 문서는 계속 차단한다.
- **동작상 큰 제한:** 이 안전장치는 모순을 자동으로 이해하거나 빠진 조건을 추출하지 않는다. 오탐을 피하기 위해 정상적인 AI 쉬운 설명도 함께 숨긴다. 현재 상품 분석의 정상 응답은 모두 `partial`이며, 문구의 의미와 조건을 사람이 원문으로 확인해야 한다. 이는 원본 응답의 품질을 수정한 것이 아니고 완성된 자동 분석 기능이 아니다.
- `web_static/products.js`: 모든 부분 완료를 인용 문자열 오류로 단정하던 문구를 실제 추가 확인 상태에 맞게 바꿨다. `README.md`도 변경된 표시 범위를 설명한다. 분석 규칙 파일은 수정하지 않았다.
- `tests/test_product.py`, `tests/test_web.py`, `tests/test_woori_regression.py`: 새 안전장치에 맞게 기존 기대 동작을 조정하고, 가상 모순 및 저장 응답 재처리 검사를 추가했다. 실제 저장 응답 테스트는 사용자 로컬 검증 자료가 없으면 건너뛴다.

## 기본 PASS 항목의 보존 여부

| 항목 | 오프라인 재처리 결과 |
|---|---|
| 기본금리 | 금리 숫자 2.60%·2.80%·2.20%는 검증된 P0016 인용에 남아 있다. 하지만 AI의 기간별 쉬운 설명은 숨겨지므로 **기존 표시가 완전히 유지된 것은 아니다**. 기간 제목 P0015는 해당 AI 사실이 인용하지 않아 별도 원문 확인이 필요하다. |
| 최저금리 | 3개월 이상 네 행의 0.15%와 계산식은 일치한 P0028~P0030 인용에 남아 있다. AI의 해석은 `needs_review`이므로 완전한 자동 판정으로 표시되지 않는다. |
| 수수료 미확인 | 무료로 단정하지 않고 확인 안내를 유지한다. 다만 기존 모델의 구체적인 미확인 문구도 모순 가능성 때문에 숨겨, 수수료 종류별 미확인 상태를 자동으로 구분하는 기능은 보존되지 않았다. |

수정 전 저장 결과는 금리 사실 3개와 중도해지 사실 7개가 `found`, 금리 사실 1개가 `validation_failed`였다. 수정 후 각각 3개와 7개는 `needs_review`, 잘못된 인용 1개는 계속 `validation_failed`다. 날짜 근거 실패와 전체 `partial`은 유지됐다. 기존 원본 응답의 SHA-256은 `2b85e015e5973a7906e2abfc3398e23ca06af8cd39bcc7c0b99637ba345a2825`다.

## 실행 결과

- 변경 전 Python 테스트 40개 통과. 변경된 동작에 맞춰 일부 기대값을 수정한 후 테스트 45개 통과(저장 실제 응답 재처리 3개 포함).
- 브라우저 검사는 로컬 모의 서버를 사용해 통과했다. 기본 제한 환경에서는 브라우저 연결이 끊겼으나 권한을 올린 로컬 재실행은 통과했고, API 호출은 없었다.
- 추가 유료 API 호출 0회. 실제 모델이 누락과 모순을 더 이상 생성하지 않는다는 주장은 할 수 없다.
