# 문단 ID 기반 실제 API 검증 보고서

> 이 보고서는 실제 API 검증 당시의 결과입니다. 이후 기본금리 중복과 일부 우대·중도해지 화면 표시가 수정됐으며, 수정 후 추가 실제 API 정확도 검증을 했다는 뜻은 아닙니다. API 원본 응답과 감사 기록은 저장소에 포함하지 않습니다.

**대상:** 우리 첫거래우대 정기예금 상품설명서

**최종 판정: PARTIAL**

새 문단 ID 스키마는 실제 API에서 수용됐고 반환된 ID도 모두 입력 문서에 존재했다. 그러나 모델 원 응답에는 우대조건의 논리, 중도해지 기간과 날짜 상태에 오류가 남았다. 화면은 잘못된 모델 설명을 확정 표시하지 않았지만 우대 상한과 마케팅 동의 유지 조건을 기본 화면에서 읽을 수 없었다. 따라서 한 번의 성공과 ID 존재만으로 분석 정확도를 통과로 판정하지 않는다.

## 모델·실행 확인

- [OpenAI GPT-4.1 mini 공식 모델 문서](https://developers.openai.com/api/docs/models/gpt-4.1-mini)는 Chat Completions와 Structured Outputs를 지원한다고 명시한다. 로컬에서 JSON Schema의 객체 필수 필드·`additionalProperties: false`, 문단 ID 전용 근거 및 세 개 우대조건 필드를 확인했다. 이는 사전 호환성 확인이며 의미 정확도를 보장하지 않는다.
- 실제 호출 전 Python 테스트 62개 통과. 규칙 파일 전문과 고유 ID 76개, 하나의 사용자 문서, system/user 분리 및 모의 오류 시 1회만 전송함을 확인했다.
- `gpt-4.1-mini`로 **실제 요청 1회**, HTTP 200, `finish_reason=stop`. 실제 응답 모델은 `gpt-4.1-mini-2025-04-14`다. 재시도나 추가 유료 호출은 없었다. 입력은 `input_verified.txt`이고 예상 정답표와 보고서는 전송하지 않았다.
- 요청 ID `비공개`, 응답 ID `비공개`. 입력 14,230 / 출력 1,581 / 총 15,811 토큰. 키와 문서 본문은 운영 로그에 출력하지 않았다.
- API 응답 원본 (로컬 보관, 저장소 제외), 호출 기록 (로컬 보관, 저장소 제외), 검증 결과 (로컬 보관, 저장소 제외), 브라우저 검사 (로컬 보관, 저장소 제외)는 이전 파일과 별도로 저장했다. 응답 원본 SHA-256은 `529c4d8d465d5f7b5f31a1783a4a3a4c88d57e9e6d7f59bd329d79bfbd2c73d1`이다.

## ID와 의미 검증

- 모델이 반환한 근거 참조는 **16개(서로 다른 ID 14개)**이며 모두 `document_id`와 `block_id`로만 구성됐다. 16개 모두 실제 입력의 지정 문단에 존재했다. 이 숫자에는 반복 ID와 날짜 근거가 포함되며 의미까지 정확한 사실 수가 아니다.
- 화면에서 서버가 가져온 원문 근거 요소 26개는 모두 정리 입력의 지정 문단과 일치했다. 중복 참조가 포함된 요소 수다. 정리 입력의 `|`와 병합 셀 표기는 PDF 레이아웃을 정리한 것이므로 입력 문자열 일치가 PDF 문자 배열의 완전 일치를 뜻하지 않는다.
- 모델은 문서 날짜를 `미확인`으로 적으면서 상태는 `found`로 반환했다. P0014 자체는 존재하고 PDF의 금리 기준일을 담지만, `미확인`이라는 값은 그 문단에 없다. 날짜 근거는 `validation_failed`, 전체 처리는 **부분 완료**로 남았다.

## 브라우저에서 확인한 범위

실제 API 응답을 저장한 후, 로컬 웹 서버의 모델 함수를 그 **저장된 실제 응답으로 대체**해 브라우저 요청을 재생했다. 이 단계의 OpenAI API 호출은 0회다. 브라우저에서 새 유료 요청을 직접 실행한 것은 아니다.

- 세 카드, 부분 완료 경고, 추가 확인 안내와 원문 근거의 기본 접힘을 확인했다. 우대조건 ①~③은 기본 화면에 표시됐고 상한·마케팅 동의·②의 기간 정의는 근거를 펼쳐 확인했다.
- 기본금리 표, 중도해지 계산식, 원문 근거가 펼쳐졌다. 320px 화면에서 가로 넘침이 없었고, 모의 오류 시 이전 결과가 남지 않았다.
- 화면의 일부 설명은 아직 원문을 확인해야 한다. 특히 모델의 ‘모두 충족’ 주장은 화면에 확정 표시되지 않았고, 상한과 동의 유지 조건은 기본 화면에 독립된 쉬운 설명으로 보이지 않는다. 기본금리 요약 세 번 중복도 남아 있다.

## 남은 제한과 포스터 판정

1. 모델이 반환한 ID와 서버의 원문 복사는 작동했지만, 조건 논리와 종료일의 정확성을 보증하지 못했다.
2. 날짜 상태 오류로 부분 완료이며, 우대조건의 범위·상한·동의 요건은 추가 확인이 필요하다. UI의 중복 금리 표시와 원문에만 있는 핵심 조건도 남아 있다.
3. 한 상품설명서와 한 번의 새 응답만 검증했다. 포스터에는 **문단 ID 기반 원문 연결과 확인 상태 구분을 구현했다**고 설명할 수 있지만, 모든 우대조건을 정확하게 자동 검증한다고 단정할 수 없다.

따라서 포스터 핵심 기능 기준 최종 판정은 **PARTIAL**이다.
